# Defect Log

Found during the 2026-09-21 historical audit. Reported only; NOT fixed (audit scope forbids production changes). Each needs its own change request.

- DEF-001 [medium, open, design gap]: Verified domain ownership is not consulted by `POST /v1/emails` (`internal/api/email_handler.go`); any tenant can submit any From domain. See RSK-006.
- DEF-002 [medium, open, incomplete feature]: DSNs are built and serialized in `worker.handleTerminalFailure` then discarded; senders receive no bounce email. See RSK-005.
- DEF-003 [low, open, test scaffold hazard]: `newMux` in `internal/api/routes.go` defaults to a zero-byte-key `SecretBox` and an unrestricted `URLPolicy` when no `routeServices` are passed. Production is unaffected (`api.Config.Webhooks` is required and validated) but tests or future callers using the default would encrypt secrets with an all-zero key.
- DEF-004 [medium, FIXED in v0.23, found during Compose e2e]: `worker.runWorker` returned on ANY `Queue.Claim` error, so a Redis outage made `Pool.Run` exit and `runComponents` stopped the whole process (liveness lost, no recovery). Fix: log, count, back off 1 s and retry unless the context is done or the queue is closed (`internal/worker/worker.go`; test `TestWorkerSurvivesTransientQueueClaimFailureAndRecovers`). Durable semantics unchanged. The component-exit-stops-process design (`5ebd574`) is otherwise retained.
- DEF-005 [medium, FIXED, Greptile PR #14 P2]: `ClaimWebhookDelivery` "one active claim per tenant" guard could race: concurrent transactions each saw no committed `delivering` row and claimed different pending rows. Fix: per-tenant `pg_advisory_xact_lock` then a fresh re-check; a busy tenant is skipped so other tenants' work is still claimed. Test `TestWebhookOneActiveClaimPerTenantUnderConcurrency`.
- DEF-006 [high, FIXED, Greptile PR #14 P1]: SMTP-only mode (no `DATABASE_URL`) never started the operator listener, so `/metrics` and `/health/*` were unreachable. Fix: `serve()` now runs the operator listener (readiness has no dependencies there). Test `TestSMTPOnlyModeServesOperatorEndpoints`.
- DEF-007 [medium, FIXED, Greptile PR #14 P2 security]: webhook creation returned raw resolver errors (internal DNS server addresses) as a 422. Fix: resolver failures map to `ErrDNSUnavailable` (503 `destination_dns_unavailable`, no detail); NXDOMAIN stays a 422 with a stable message. Tests in `internal/webhook` and `internal/api`.
- DEF-008 [medium, FIXED in v0.24]: the Docker runtime image (alpine) had no CA certificates, so every certificate verification in the container (new SMTP STARTTLS, and the existing HTTPS webhook client) would fail. Fix: `apk add ca-certificates` in the Dockerfile; verified in the built image (145 roots).
- Observed, not a defect: prompt/roadmap claimed HEAD `4148ad6`; the repository was at `a8849e0` (v0.23 plus review/CI fixes and README, merged to main as `37b384d`). Work proceeded from the repository state.
- DEF-009 [low, FIXED before commit, v0.25]: the first draft of `.env.example` set `MAILX_RELAY_PORT=587` with an empty host, which the new startup validation correctly rejects (port without host); a copied example would have failed to start. Relay variables are now commented placeholders. Found by review, not shipped.
- DEF-001 [RESOLVED in v0.26]: verified domain ownership is now enforced on send (see `docs/design-v0.26.md`); RSK-006 is closed.
- DEF-010 [low, FIXED before commit, v0.26]: the first DNS-name index assertion expected `uq_domains_tenant_active_name` but the planner correctly prefers `uq_domains_active_verified_name` for a name lookup; the test now accepts either `uq_domains_*` name index. Test expectation only, no product change.
- Test-suite consequence: pre-v0.26 API tests sent from unverified domains; they now verify a test domain first (`verifyTestDomain`). One idempotency test that used the same From for two tenants now uses a second tenant's own domain because only one tenant may hold a verified name.
- DEF-011 [medium, FIXED, Greptile PR #15 P2]: `POST /v1/domains/{id}/dkim` generated an RSA-2048 key before checking the one-pending-key rule, so repeated or concurrent requests burned CPU only to return 409. Fix: check for a pending key first and bound concurrent generation to 2 with a cancellable wait (`TestCreateKeyDoesNotGenerateWhenPendingExistsAndBoundsConcurrency`).
- DEF-012 [low, FIXED, Greptile PR #15]: DKIM verify swallowed a database error from the disambiguating lookup and returned 404; it now returns 500 (`TestDKIMVerifyDatabaseFailureIsNot404`).
- DEF-013 [low, FIXED, Greptile PR #15]: the three DKIM operations did not document the 500 response in OpenAPI; added.
